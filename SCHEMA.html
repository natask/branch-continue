Schema Workbench

One card. Three storage shapes.

Start from a single canonical card model. Project it into loro for editing, search for retrieval, and omni for unified pulls across UI, agents, and future tooling.

Storage Rules
  • Loro owns authored state Markdown body, lineage, lightweight metadata, and future local editing containers.
  • Search owns flattened recall Plaintext, tags, aliases, filters, and ranking hints only. No canonical truth lives here.
  • Omni owns cross-surface retrieval One normalized record for commands, sidebars, agents, and future cross-entity joins.

    Practical rule: read from loro when editing, read from omni when listing or commanding, and rebuild search from the current materialized state.

    Responsibility Matrix

    Each layer has one job. Keep the seams explicit so migrations stay manageable.

    Loro

    Editable truth, branch lineage, local UI state, future patch-friendly evolution.

    Search

    Fast recall, ranking, fuzzy match, filterable text retrieval, no ownership of truth.

    Omni

    Normalized pull surface for lists, commands, agents, and any entity beyond pages.
