Schema Workbench

One card. Three actual integration feeds.

Start from a single canonical card model. Project it into loro for editing, @moa.os/search for ranking and matching, and omnitab for command presentation.

Storage Rules
  • Loro owns authored state Markdown body, lineage, lightweight metadata, and future local editing containers.
  • Search owns flattened recall Derived text, aliases, and ranking hints only. No canonical truth lives here.
  • OmniTab owns command interaction It consumes command items and runs actions. It does not own persistence or canonical data.

    Responsibility Matrix

    Each layer has one job. Keep the seams explicit so migrations stay manageable.

    Loro

    Editable truth, branch lineage, local UI state, future patch-friendly evolution.

    Search

    Fast recall, ranking, fuzzy match, filterable text retrieval, no ownership of truth.

    OmniTab

    Command palette UI over derived command items, with bang filters, recency, and actions.
