# Backbone source format

The existing Org source file is the portable record. Each note has a stable `BRANCH_CONTINUE_NOTE_UID` property. Its normal body is the latest materialized text, including source-relative audio links and portable concept and page-instruction metadata. Older Org files remain readable; their first saved edit records a baseline and assigns a stable UID.

History is stored in reserved one-line fields within that same note:

- `#+BACKBONE_EVENT: {JSON}` holds a complete page version: `id`, `noteUid`, `sequence`, `at` (ISO timestamp), `actor` (`user`, `codex`, or `system`), `kind` (`created`, `edited`, `snapshot`, or `restored`), `title`, `body`, `tags`, `timestamp`, `parentNoteId`, and `disposition`. Later versions have `previousVersionId`. Restores can include `restoredFrom` and a human-readable `label`.
- `#+BACKBONE_RECORD: {JSON}` holds a domain event: `id`, `noteUid`, `sequence`, `at`, `actor`, `type`, and `payload`. Body changes automatically produce `concepts.changed`, `audio.references-changed`, and `page.instructions-changed` records with `{before, after}` values when those fields change. Other app features can append typed records through `QuickNoteCreateRequest.backboneRecords`.

JSON string escaping keeps old multiline bodies and Org headlines inside one physical line. Neither field appears in the active note body or search results. Updating a note preserves every existing reserved field verbatim, including malformed or future fields this version cannot interpret. Unknown Org properties also survive edits. Invalid fields are excluded from replay; their original text remains in the source.

`readBackboneLog(sourceContent)` exposes one logical event stream across every page. It normalizes versions to the same `{id, noteUid, sequence, at, actor, type, payload}` envelope as records, using `page.created`, `page.edited`, `page.snapshot`, and `page.restored` event names. Each newly written field receives the next monotonic sequence across the whole source file, independent of device clocks. Events sort by that persisted sequence, with source position breaking sequence ties. Older fields without a sequence replay first in their existing physical source order; their per-page causal chains remain intact. Existing fields are never rewritten merely to assign a sequence. Timestamps describe when a device observed an operation; they do not control replay order. Duplicate event IDs are read once. Physical fields remain grouped with their Org note for compatibility.

`replayBackboneLog(events)` reconstructs a map from stable page UID to its latest complete version, domain records, concept hierarchy, audio references, and page instructions. Replay requires only the source text, without localStorage or IndexedDB. A version whose parent contradicts the previously replayed version is rejected as a divergent history rather than silently choosing one branch. `replayBackboneVersions` provides the corresponding single-page operation.

Snapshots record unchanged text. Restore, file undo, and file redo append fresh versions. Undoing creation records a discarded disposition; it retains the page and its events. Offset-only commands from older device caches cannot rewrite a file containing Backbone versions. New semantic commands check the current materialized page before applying, so an unrelated page change survives while a conflicting same-page change blocks undo.

An external editor may update the materialized body without producing events. On the next app save, Backbone first records that observed state as a system edit, then records the app edit. It cannot recover intermediate states that an external editor never saved in this log. The synced-folder provider transports the file and audio; Backbone does not implement its own transport or claim to resolve concurrent sync-provider conflict copies automatically.
